# QQ群管 (qflarebot-plugin-qqadmin)

[QFlareBot](https://github.com/QFlareBot/QFlareBot) 的群管插件：禁言、撤回、违禁词、刷屏检测、投票禁言、进群审核、进群欢迎与禁言、退群通知与拉黑。每个群可以单独配置，面板里有和上游一样的「默认群 + 各群」配置页面。

移植自 AstrBot 插件 [astrbot_plugin_qqadmin](https://github.com/Zhalslar/astrbot_plugin_qqadmin)（作者 Zhalslar）。上游只支持 OneBot（NapCat），这边跑在 QQ 官方机器人上：官方接口有的都保留，文案与上游一致；官方接口没有的去掉了，并修掉了上游的一些 bug（见下文）。

## 安装

面板 → 插件 → 安装插件，粘贴本仓库链接。需要：

- **机器人 0.5.0 以上**：用到了 `ctx.botAdmins` 和 `mentionedUsers()`（契约版本 3），老版本安装时会被拦下。
- **D1**：配置、投票、入群失败次数都存在 D1 里，不用 KV。
- **机器人是群管理员**：禁言、撤回别人的消息、审批入群申请都要。
- **群主打开两项权限**（群里点机器人头像 → 右上角）：
  - 获取群内全部消息：违禁词、刷屏检测要看到每一条消息。
  - 主动消息：入群申请通知、进群欢迎、退群通报、投票到点的结算结果都不是在回复谁，要主动发。
- QQ 开放平台回调配置里的事件全部勾选（部署文档里本来就是这么写的）：入群申请、成员进退群都靠事件推送。

## 指令

群里 @机器人 时可以不打 `/`。只能在群里用。发 `/群管帮助` 看全部指令。

| 指令 | 说明 | 默认权限 |
| --- | --- | --- |
| 禁言 <秒数> @用户 | 对指定成员禁言，不写秒数用随机时长 | 管理员 |
| 解禁 @用户 | 解除指定成员的禁言 | 管理员 |
| （引用消息）撤回 | 撤回引用的那条消息（2 分钟内、机器人收到过或发出的） | 成员 |
| 设置禁词 <词1 词2...>（别名：禁词、违禁词） | 覆写违禁词；`+词 -词` 增删；不带参数查看 | 管理员 |
| 内置禁词 开/关 | 开启或关闭内置违禁词检测 | 管理员 |
| 禁词禁言 <秒数> | 触发违禁词后的禁言时长，0 表示不禁言 | 管理员 |
| 刷屏禁言 <秒数> | 刷屏的禁言时长，0 表示关闭 | 管理员 |
| （自动）违禁词检测 | 撤回并按设置禁言，Bot 管理员不查 | — |
| （自动）刷屏检测 | 0.5 秒内连发 5 条即禁言 | — |
| 投票禁言 <秒数> @用户 | 发起禁言投票 | 成员 |
| 赞同禁言 / 反对禁言 | 投票；够票立即生效，到点按多数结算 | 成员 |
| 进群审核 开/关 | 进群审核总开关 | 管理员 |
| 进群白词 <关键词...> | 答案命中就自动批准 | 管理员 |
| 进群黑词 <关键词...> | 答案命中就自动拒绝 | 管理员 |
| 未命中驳回 开/关 | 没命中白词就自动驳回 | 管理员 |
| 进群次数 <次数> | 没命中关键词多少次后拉黑，0 表示不限制 | 管理员 |
| 进群黑名单 +@用户 -@用户 | 增删进群黑名单，也可以直接写 openid；不带 +- 就整表覆写 | 管理员 |
| （引用进群申请）批准 / 驳回 <理由> | 审批进群申请；通知上也有按钮 | 管理员 |
| 进群欢迎 <欢迎语> | 新成员进群时发，支持 `{nickname}` | 管理员 |
| 进群禁言 <秒数> | 新成员进群自动禁言，0 表示不启用 | 管理员 |
| 退群通知 开/关 | 有人主动退群时通报 | 管理员 |
| 退群拉黑 开/关 | 主动退群的人拉黑，下次申请自动拒绝 | 管理员 |
| 群管配置 <配置串> | 查看或修改本群配置（每行「中文键: 值」） | 管理员 |
| 群管重置 <all> | 本群恢复跟随默认配置；`all` 是全部群，只有超管能用 | 管理员 |

开关和查看类的命令不带参数就是查看当前设置。

权限分四档：超管（面板「设置 → 权限」里的 Bot 管理员）> 群主 > 管理员 > 成员。每个命令的门槛都能在配置页面的「指令权限管理」里按群改。

## 配置页面

面板侧栏「插件页面 → 群管配置」：

- 左边是群列表：最上面是「默认群」，新群和跟随默认配置的群都用它；下面是机器人待过的群。
- 右边是选中那个群的配置。第一项「跟随默认配置」开着时，这个群直接沿用默认群，下面的配置项不能改；关掉就保存它自己的一份。
- 切换群时自动保存当前的改动；指令权限管理默认折叠。

群里用命令改设置，和在页面上改是同一份数据。

## 与上游的不同

**QQ 官方机器人没有的东西**

- 官方接口里没有的：全员禁言（连带宵禁）、改群名片、头衔、设管理员、群精华、群头像、群名、群公告、群文件。
- 平台标着「内邀」、没开白名单用不了的：踢人、群拉黑、群友信息、清理群友。
- 没有历史消息：`撤回 @某人 数量` 去掉了，只保留引用撤回。
- 群里引用消息时，平台只给被引用消息的索引，不给撤回要用的消息 id。框架在内存里记着最近 2 分钟收到和发出的消息（平台本来就只能撤回 2 分钟内的消息），引用时靠它查，所以只撤得回机器人收到过的消息：群主没开「获取群内全部消息」时，群友没 @ 机器人的消息撤不了；偶尔请求落到另一个 Worker 实例上也会查不到。查不到时回「没找到这条消息，撤回不了」并说明原因，同时打一条 warn 日志「群管撤回没拿到被引用消息的 id」：带推送里的引用索引、这个实例最近 2 分钟收到这个群多少条消息、平台给的机器人群内状态（bot_state），用来分清是消息没推过来还是落在了别的实例。需要机器人 0.5.0 以上。
- 撤回被平台拒绝时说出原因：超过 2 分钟回「消息发送超过 2 分钟，无法撤回」；没权限时在上游的「我无权撤回这条消息」后面补一句，机器人当管理员也撤不了群主和其他管理员的消息。原因同时记进 warn 日志。
- 没有 QQ 号，也拿不到 QQ 等级：进群黑名单记 openid（用 @ 加，或者退群拉黑、黑词拉黑自动加）；进群等级门槛去掉了；要看群等级的「高等级成员」权限去掉了，上游默认给它的「批准/驳回」改成管理员。
- 查不了群名片：提到某人时用消息里带的名字，没有就写成 @ 那个人。
- 没有 LLM 工具调用：上游注册的 LLM 工具去掉了。
- 引用进群申请审批之外，通知上多了「批准 / 驳回」按钮。按钮谁点得动按「批准/驳回」的权限设：超管只有 Bot 管理员点得动，群主和管理员是平台的「仅管理员」，成员所有人。
- 「进群事件仅通知bot管理员」改成私聊面板里的 Bot 管理员。
- 配置页面：官方接口不给群号，所以没有群头像和群号，群名打开页面时现查、不存。群列表是机器人收到过消息或被拉进过的群；机器人被移出群时自动清掉（上游是群人数为 0 时清掉）。主题跟随面板，去掉了上游自带的主题切换。
- `群管配置 <群号> <配置串>`、`群管重置 <群号>` 改别的群：这边没有群号，别的群到配置页面里改。
- 上游 README 里写了 `/群管帮助`，代码里却没有，这边补上了。

**修掉的 bug**

- `刷屏禁言 <秒数>` 读写的都是禁词禁言的时长，刷屏检测用的时长永远改不了。
- `禁言`、`解禁` 的权限项写成了改名的，配置里「禁言」「解禁」两项不起作用；`刷屏禁言` 用的权限项不在配置里，永远是默认的管理员。
- `禁言`、`解禁` 算出了结果却没发出去，发了命令没有任何回复。解禁原来会说「已被禁言0秒」，改成「已解除禁言」。
- `进群审核`、`内置禁词`、`未命中驳回`、`退群通知`、`退群拉黑` 不带参数时本该查看，却会被当成「关」写进去。
- 违禁词只把消息转成小写，词表里带大写字母的词永远匹配不上。
- 「主动退群拉黑」只在「主动退群通知」也开着时才生效。
- `群管重置 all` 不是超管时，会去重置一个叫 all 的群，却回「已重置本群的群管配置」。
- `群管配置` 的输出原样打印了权限、投票这些嵌套配置的字典，现在只输出能用中文键改的那些项。
- 开关类的结果显示成开/关，不再是 True/False。

## 省额度的做法

免费版 D1 每天写 10 万行，全机器人共享。这个插件：

- 三张表（群配置、进行中的投票、入群失败次数）都只有主键、没有二级索引，写一行就只算一行。
- **每条群消息 0 次写入**：违禁词、刷屏检测只读设置，读到的设置在内存里缓存一分钟，缓存命中时连查询都没有。刷屏计数和上游一样放在内存里。
- 写入只来自：群第一次出现时记一行（每个群一辈子一次）、改设置、投票（每票一行）、入群申请（失败次数、拉黑）。
- 投票到点由每分钟的定时任务结算，没有进行中的投票时只是一次空查询，不写。入群失败记录 30 天没再申请就清掉。

## 开发

```bash
# QFlareBot 与本仓库并排放
git clone https://github.com/QFlareBot/QFlareBot
(cd QFlareBot && pnpm install --filter '@qqbot/plugin-cli...' && pnpm --filter '@qqbot/plugin-cli...' build)
cd qflarebot-plugin-qqadmin
npm install
npm test          # 用 node:sqlite 跑真实 SQL，并套用框架的表名检查
npm run typecheck
npm run sync      # 打包配置页面、构建并更新 manifest.json
```

配置页面的源码在 `ui/`（TypeScript，不用框架）。构建机不跑前端构建，`npm run build:ui` 把它打成单个 HTML 写进 `src/web/page.generated.ts`，随源码提交；CI 会检查它和 `ui/` 对得上。

需要 Node 22.13 以上（`node:sqlite`）。
